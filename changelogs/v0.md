# Changelog
---

## [0.3.1] - 2026-09-22

### Fixed

- **ZeptoMailHttpSender fetch binding on strict runtimes**:
  - `ZeptoMailHttpSender` now binds `fetch` to `globalThis` to prevent "Illegal invocation" errors on strict-`this` runtimes (undici, Cloudflare Workers `workerd`). On Node < 18 without a global `fetch`, a helpful error message guides users to pass a custom `fetch` via `ZeptoMailHttpConfig`.

---

## [0.3.0] - 2026-09-20

### Added
- **`ZeptoMailHttpSender` & `ZeptoMailHttpConfig`**:
  - Renamed canonical Zoho ZeptoMail HTTP adapter to `ZeptoMailHttpSender` to clearly reflect its native `fetch` HTTP transport nature.
  - Introduced `ZeptoMailHttpConfig` as the canonical configuration interface.
- **Auto Plain-Text Fallback in `sendRaw`**:
  - `mailer.sendRaw({ to, subject, html })` automatically derives clean, readable plain-text fallback content using `htmlToPlainText(options.html)` when `text` is omitted.
- **RFC 5322 Email Address Parser**:
  - Added tree-shakeable `parseEmailAddress(input: string): EmailAddress` utility for parsing formatted strings like `"Jane Doe <jane@example.com>"` into structured address objects.

### Deprecated
- **`ZeptoMailSender` & `ZeptoMailConfig`**:
  - Marked `@deprecated`. Use `ZeptoMailHttpSender` and `ZeptoMailHttpConfig` instead. Retained as aliases until `v1.0.0`.
- **`ZeptoMailHttpSender.prototype.sendEmail(...)`**:
  - Marked `@deprecated`. Use `sender.send({ to, subject, html, text, ... })` instead. Retained until `v1.0.0`.
- **Positional `mailer.send(to, template, toName)`**:
  - Marked `@deprecated`. Use `mailer.send({ to, template, ... })` instead. Retained until `v1.0.0`.
- **`mailer.sendSimpleMessage(...)` & `mailer.buildPlainTextMessage(...)`**:
  - Marked `@deprecated`. Use `mailer.sendRaw(...)` and `mailer.render(...)` / `buildPlainText(...)` instead. Retained until `v1.0.0`.
- **`EmailService`**:
  - Marked `@deprecated`. Use `MailKit` instead. Retained until `v1.0.0`.
- **`BaseEmailDto`**:
  - Marked `@deprecated`. Use `EmailTemplateDto` instead. Retained until `v1.0.0`.

## [0.2.0] - 2026-09-20

### Added
- **Top-Center Brand Logo**:
  - Added support for displaying a brand or application logo centered above the hero banner via `logoUrl`.
  - Strict HTTP/HTTPS validation prevents rendering malformed or local paths.
  - Added `logoUrl` support in `EmailTemplateFactory` default branding and template override options.
- **Pre-rendered Template Preview**:
  - Added `demo-newsletter.html` to the repository root for inspecting responsive email output without installing or building.
- **Canonical `EmailTemplateDto`**:
  - Standardized on `EmailTemplateDto` as the primary interface name for email data transfer objects.

### Deprecated
- **`BaseEmailDto`**:
  - Marked `@deprecated` in favor of `EmailTemplateDto`.
- **`EmailService`**:
  - Marked `@deprecated` in favor of `MailKit`.
- **Positional `send(...)` Signature**:
  - Marked `@deprecated` in favor of `send(options: SendTemplateOptions)`.

---

## [0.1.0] - Initial Release

### Added
- Initial release of `ts-mailkit`.
- Modular, zero-runtime-dependency email composition and dispatch library for TypeScript and edge runtimes.
- Decoupled `IEmailSender` interface with built-in `ZeptoMailSender` (native `fetch`), `MemoryEmailSender` (testing), and `ConsoleEmailSender` (dev).
- Strongly typed email DTO schemas and `EmailTemplateFactory` (verification, password reset, 2FA, magic link, newsletter, simple message).
- Responsive `DefaultEmailRenderer` with plain-text fallback generation.
- Client facade `MailKit` with `createMailKit` and dynamic multi-tenant brand name resolver.
- Dual ESM (`dist/index.js`) and CommonJS (`dist/index.cjs`) distribution with declaration maps.
